# **SYSTEM BLUEPRINT — “Microinsurance Fraud Detection Service”**

---

## **1. Overview**

This system runs as an **independent microservice** that detects fraud in insurance claims.
It exposes **RESTful APIs** that any external system can consume.

When a new claim is submitted to the main insurance platform, the platform sends it to this fraud detection API. The service analyzes it using AI and responds with a **fraud score** and **recommendation**.

---

## **2. Core Workflow**

### **Stage 1: Claim Submission (External System)**

* A user or insurance agent submits a claim via the **main insurance system**.
* The main system calls this service’s **`/api/fraud/analyze`** endpoint with claim details:

  ```json
  {
    "claim_id": "CLM00123",
    "client_id": "C102",
    "amount": 5000,
    "claim_type": "Health",
    "claim_date": "2025-11-04",
    "location": "Nairobi, Kenya",
    "previous_claims": 3
  }
  ```

---

### **Stage 2: Fraud Detection Microservice**

1. **Data Preprocessing Layer**

   * Validates input.
   * Normalizes numeric values (e.g., amount).
   * Encodes categorical data (claim type, location).
2. **AI Model Layer**

   * Uses a trained **TensorFlow.js model** (or calls a Python FastAPI ML endpoint).
   * Outputs a **fraud probability score** between `0 and 1`.
3. **Decision Layer**

   * If `score > 0.8` → mark claim as suspicious.
4. **Database Layer**

   * Store claim record and result in **PostgreSQL**.
5. **Response**

   * Send back a JSON response:

     ```json
     {
       "claim_id": "CLM00123",
       "fraud_score": 0.87,
       "flagged": true,
       "decision": "Review Required"
     }
     ```

---

### **Stage 3: Main System Action**

* The **main insurance system** receives the response:

  * If **flagged = false**, proceed with automatic claim approval.
  * If **flagged = true**, route the claim to **manual review queue**.
* Logs or displays the score in the main system’s admin dashboard.

---

### **Stage 4: Dashboard & Monitoring**

Fraud Detection Service provides a **React-based dashboard** for analytics:

* Total claims processed
* Fraud trends over time
* Heatmap of fraud-prone regions
* Claims comparison by type or agent
* Alerts and retraining status

## **4. Subsystem Breakdown**

### A. Backend (Node.js + Express)

Handles:

* Claim submission & analysis endpoints
* Fraud scoring
* Model loading & prediction
* Data persistence (PostgreSQL)
* External API integration

**Main endpoints:**

| Endpoint             | Method | Description              |
| -------------------- | ------ | ------------------------ |
| `/api/fraud/analyze` | POST   | Analyze a new claim      |
| `/api/fraud/claims`  | GET    | Retrieve all claims      |
| `/api/fraud/stats`   | GET    | Return fraud analytics   |
| `/api/fraud/retrain` | POST   | Trigger model retraining |

---

### B. AI/ML Layer

Two approaches:

1. **TensorFlow.js** (all-JS)

   * Runs inside Node.js
   * Portable and deployable anywhere
2. **Python Microservice** (recommended for stronger ML)

   * Train & serve model using FastAPI
   * Node.js calls Python API for fraud scoring
   * Model can use scikit-learn / XGBoost

**Sample model input features:**

* `claim_amount`
* `claim_type`
* `frequency_of_claims`
* `location_risk_score`
* `claim_time_gap`
* `previous_fraud_flags`

---

### C. Database (PostgreSQL)

**Tables:**

1. `claims` — stores all analyzed claim data.
2. `fraud_results` — stores fraud probability and metadata.
3. `users` (optional) — for authenticated dashboard users.
4. `logs` — stores system events for auditing.

---

### D. Dashboard (React + Tailwind + Recharts)

Pages:

1. **Home Dashboard:** Overview of system stats
2. **Flagged Claims:** Table of all suspicious claims
3. **Analytics:** Charts & filters (fraud by region/type/time)
4. **Model Management:** Retrain or view model accuracy

---

### E. Integration Layer (APIs to Main System)

Future plug-in options:

* **REST Hooks:** when new claims are submitted or flagged.
* **WebSocket feed:** for real-time updates to the main dashboard.
* **Webhook callbacks:** to trigger notifications in the parent system.
